## 4. Problem Statement & Healthcare Use Case
India has one of the world's largest Type 2 Diabetes populations, yet care is reactive: patients learn of glucose excursions after the damage is done. This PoC builds a **Digital Twin of a T2D patient** that fuses historical EHR data with real-time wearable/CGM streams to **predict a hyperglycemic event (glucose > 180 mg/dL) 2 hours in advance**, letting a doctor intervene early and test what-if scenarios (e.g., a post-meal walk).

- **Static stream (EHR, synthetic):** age, BMI, HbA1c, diabetes duration, family history, metformin use
- **Dynamic stream (synthetic CGM/wearable):** glucose (5-min), heart rate, HRV, steps, previous-night sleep
- **Output:** 2-hour-ahead risk score + conceptual clinician dashboard (`dashboard.html`)

## 5. Technical Stack
Python 3.12, NumPy, pandas, scikit-learn, HTML/CSS/JavaScript (dashboard)

## 6. AI/ML Model Details
- **Model:** HistGradientBoostingClassifier (scikit-learn)
- **Features:** EHR (6) + CGM lags/deltas/rolling stats (6) + wearable (5)
- **Label:** max glucose in next 120 min > 180 mg/dL
- **Split:** by patient (300 synthetic patients x 14 days; 25% of patients held out)

| Input streams | ROC-AUC | PR-AUC | Recall | Precision |
|---|---|---|---|---|
| CGM only | 0.960 | 0.938 | 0.761 | 0.962 |
| CGM + wearable | 0.993 | 0.986 | 0.932 | 0.935 |
| **EHR + CGM + wearable (fused)** | **0.996** | **0.990** | **0.947** | **0.945** |

> **Limitation:** Data is fully synthetic, generated by our own simulator (`twin_poc.py`), so these scores reflect the simulator's structure and **will not transfer to real patients**. Next step: validate on open datasets (e.g., Synthea EHRs, public CGM datasets).

## 7. Data (sandbox rules)
Only synthetic data is used, generated in `twin_poc.py`. No real patient data; DPDP/HIPAA compliant by design.
